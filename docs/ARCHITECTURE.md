# Architecture
Proposed portable C++ core with no ESP-specific dependencies; host test runner, data-driven tech catalog, seeded RNG. Verify target SDK and hardware before selecting drivers.
Fixed deterministic ticks independent of rendering: environment, decisions, reservations/actions, births/deaths, knowledge, history. Stable ID iteration; bounded queues; read-only rendering snapshots. Inactive regional simulation may reduce update frequency but preserve identities and rules. Explicit embedded status/error logs, watchdog, performance metrics.
## Persistence
Two alternating checksummed checkpoints and append-only event segments. Write, sync where supported, validate readback then publish manifest. Retain last verified generation. Replay complete validated events with matching world and event IDs only; report corrupt tail. Power-cut test actual filesystem; rename alone is not a durability guarantee. Batch writes, monitor wear/free space; export archives or safe pause before data loss; never silently drop genealogy. Finite media requires archival expansion.
## Migration
Export manifest, schema/rules versions, RNG, full world, catalog and historical segments. Validate checksums, invariants and golden replay before import; keep source intact. Hardware-independent IDs and state, external backups. Original ESP32 is founding device; future hardware increases simulation/storage capability while preserving the original fixed world geometry and identities; it does not expand terrestrial boundaries.
## Optional streaming
Publish a bounded read-only snapshot/event stream; separate rendering/broadcast host. Stream failure never alters simulation, blocks ticks or requires internet for core operation. See LIVESTREAM.md.

## Approved design boundaries
Official observer interface is read-only with respect to simulation; maintenance/backup and view/audio settings are isolated from world transitions. Preserve founder personal knowledge separately from mortal knowledge, simulated records and durable observer history. Use shared decay/resource transactions for complete physical disappearance of abandoned structures. Future society, belief, cultural/language, diplomacy and space systems extend versioned state only after primitive core and persistence are stable; no automatic territory growth or hidden intervention. Maintain a quiet default.

## Implemented host persistence slice
storage/checkpoint_fields.hpp and checkpoint.hpp provide explicit binary encoding, validation and two-generation recovery. storage/host_checkpoint.hpp is a POSIX-only file adapter using synced temporary files and alternating slots. Caller serializes access and isolates disposable world directories. Filesystem readback and simulated corruption tests pass on host; not a physical power-cut or ESP32 certification. Full archive/journal transactions, UUID, automatic checkpoint scheduling, JSON interchange and device adapter remain unimplemented. Do not use this prototype for official saves.

## Maintenance isolation and full-screen display
Observer rendering owns the full viewport; temporary overlays only. No direct reset entry point from renderer or network. A separate trusted physical-USB adapter must own authentication, session lifetime, exclusive tick pause, backup transfer and authorization. Host prototype in maintenance/host_reset.hpp validates asserted trusted context, exact paused checkpoint and backup, then stages a replacement in an empty separate directory with redundant verified saves. This is not real USB authentication, a security boundary, a physical independent-media proof or activation. Do not expose its Access fields/permit as client-controlled inputs. Production requires private session-bound nonreplayable authorization, physical disconnect handling, verified full external backup, UUID, secure activation journal and device power-cut tests. No deletion or active switch implemented.

## Lifetime identity decoupling, first slice
Separate stable identities from active array positions. Care requests, conception eligibility and pregnancy participant validation use bounded live-slot tables; they do not grow with historical population. Slots are ephemeral and cannot be persisted or retained across compaction. Existing death archive indexing/validation and admission capacity still require replacement with durable segmented history. Do not claim the 512-identity blocker closed from this refactor.

## Immutable history storage foundation
storage/history_segment.hpp reuses the canonical citizen field codec for bounded death batches; storage/host_history.hpp publishes readback-verified immutable files on host POSIX. The current world remains authoritative and unchanged by export. Next close P0 through a checkpoint-bound archive watermark and verified manifest/index, recoverable publication/retirement transaction, external genealogy resolution, UUID, and tests for actual births above 512 without record loss. POSIX hard links are not assumed available on the ESP32 storage medium. No official-world use.

## Historical identity reference index
Host-only storage/history_index.hpp checks external batches as one ordered prefix, exposes stable identity lookup and validates the combined historical view against current resident records and descendants. core/genealogy.hpp shares lineage checks with the existing runnable world validator. This host reference is not a complete World validator, embedded index or retirement transaction. Next bind a verified prefix to a checkpoint, recover interrupted handoff without loss, integrate lookup into simulation admission/validation and test actual births beyond 512. Device storage needs bounded-memory lookup, not the host map.

## Checkpoint-bound archive retirement (host prototype)
Create explicitly from a validated legacy world in a separate directory. Write immutable history batches, sync/readback, build a candidate with a reduced resident death tail, validate the combined index, then publish the next alternating PGAW checkpoint. Re-read both slots and verify consecutive generations differ only by exact retirement; return new state only after successful readback. Uncommitted segments do not change authority; identical retry is safe. Corrupt checkpoint permits read-only older fallback, but valid checksummed checkpoint with missing or invalid referenced history fails closed. No automatic repair/overwrite from degraded recovery. Legacy source remains untouched. Host reference index still uses O(history) memory. Ordinary tick entry does not accept retired worlds yet; integrate external-history-aware authoritative stepping and actual births beyond 512 next.

## External-history-aware host ticks
Shared authoritative step with storage-specific validator; legacy rejects retired worlds. Host advancement begins from exact verified disk checkpoint, refuses pending segment at watermark, advances scratch world, publishes alternate slot and validates deterministic replay on recovery. No arbitrary candidate accepted. Full history validation/replay expensive; bounded trusted index and automatic admission/cadence needed for device.

## Automatic host archival cycle
storage/host_archive_cycle.hpp provides a synchronous single-operation scheduler primitive. Recover first; refuse degraded/missing checkpoints; resume a published segment at the committed ordinal by exact retirement, else retire one full 64-record batch, else advance at most 600 ticks through verified checkpoint replay. Caller invokes repeatedly; no timer, service, concurrency, or real-time catchup implied. The 600-tick window and below-64 resident death threshold leave room under existing reservation rules; no new population quota. Existing immutable publication and readback verification remain authoritative. Host full-history validation still scales with lifetime records.

## Disk-backed historical lookup prototype
DiskHistoryIndex uses host POSIX scratch file, unlinked while open, fixed encoded rows by stable ID and CRC. Load one immutable batch at a time, validate chronology and reject duplicate/out-of-range IDs before writing rows. Full audit uses shared combined validator; read one row at a time and resolve genealogy using same lookup contract. Scratch is never authoritative; failure propagates. Memory not proportional to lifetime deaths, but disk size and full audit time scale with history. Existing runnable host map remains reference. Next integrate verified index/cache without per-tick full history scans; actual FAT32 adapter needs separate durability and performance verification.

## Integrated bounded-history host replay
Checkpoint decode, retirement and advancement now use DiskHistoryIndex. Full audits scan verified immutable-derived rows at transaction boundaries. In a closed replay, cache initial external parent/guardian records and resident identities; use the existing shared resident validator every tick without disk reads, check full state again at end. Reject pre-existing nonresident IDs even when not in cache. New birth IDs monotonic; new guardian/parent references originate from living citizens. No external mutation during replay. Scratch file rebuild and boundary audits still scale with history and require measured capacity/latency limits. No FAT32 implementation or device qualification yet.

## Host capacity preflight
Read statvfs available blocks for the actual directory. Before scratch allocation check full row file size; before creation/advancement/retirement check conservative future scratch and temporary publication budget. Refusal means no new checkpoint or history publication and caller must pause; retry only through verified recovery. Budget is advisory, not an exclusive allocation guarantee; concurrent disk use, quotas, filesystem metadata and hardware failures can still interrupt writes. Existing transactional recovery remains mandatory. No device FAT32 or 32GB hardware certification.
