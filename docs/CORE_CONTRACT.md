# Core increment 1 — provisional state and replay contract
This is an implementation subset of DATA_SCHEMA.md, not a replacement or a portable save format. Explicit disposable initialization takes an unsigned 64-bit seed. Six named SplitMix64-v1 streams derive their starting states from successive root outputs in stable order terrain, traits, environment, decisions, reproduction, research. Unsigned arithmetic wraps modulo 2^64. Range selection uses rejection before modulo; zero bound fails unchanged. Separate states isolate draw consumption between domains; they are not cryptographically independent streams. Golden seed-zero outputs e220a8397b1dcdaf and 6e789e6aa1b965f4.
World holds a monotonic uint64 clock (one tick per real second, 43200 ticks per simulated year), six states, 6000 row-major resource tiles, two immortal founder records. Four seasons derive from equal clock quarters, index 0 spring through 3 winter. Each tile starts with food/wood/water 60–100 and stone 20–60 abstract integer units. These homogeneous resource ranges are provisional, not final ecological terrain or regeneration. Founders IDs 1 and 2, at adjacent center positions, six traits (curiosity, diligence, compassion, creativity, sociability, risk tolerance) in 0–100.
Tick order in this increment: check overflow, increment clock. Rendering and real-time scheduling are not present. Store World in persistent/heap allocation on embedded targets rather than task stack; actual storage adapter pending. No birth, mortality, movement, weather, consumption or persistence behavior yet. Never use this initializer as fallback to invalid saves. Further state additions must specify invariants before implementation.
Host command: g++ -std=c++17 -Wall -Wextra -Werror -pedantic -fsanitize=undefined -Icore tests/core_test.cpp -o core-test && ./core-test

## Increment 2 — founder survival slice
Provisional test tuning, not final biology: hunger and thirst are uint8 0–100, start at zero, increase by one per 1-second tick (saturating). A founder with max need >= 12 prioritizes the larger need (ties water), consumes one unit of that resource at the current tile if available, reducing the corresponding need by up to 12; otherwise moves one cardinal tile toward a locally richer neighbor. Below threshold, curiosity (trait index 0) gives a percentage chance of one cardinal exploration move, using only the decisions stream. Stable neighbor order left/right/up/down; no diagonals, no wrapping. Consume from authoritative tile stock, not from a copy. Two founders act in ID order; the second sees the first's consumption. No regeneration, mortality, pathfinding beyond neighbors, inventory, purpose assignment or shelter yet. The action state (idle, move, eat, drink) describes the last tick. Initialization clears needs/actions on disposable reset. Reject invalid positions, needs, IDs or clock overflow before mutation, returning false for caller logging. A blocked founder remains alive; complete long-term recovery is a later gate.

## Increment 3 — renewable-resource slice
Provisional ecological rules: after a successful survival tick, every 60th tick renew all tile stocks up to their natural cap (100 units for each renewable stock); food gains 2 units in spring/summer, 1 in autumn and 0 in winter; water gains 3 in spring, 1 in summer, 2 in autumn/winter; wood gains 1 in spring/summer and 0 otherwise. Stone never regenerates. Stocks already above cap are not silently destroyed. Renewal represents natural environmental production, not an arbitrary population rescue. No random draws. Report actual aggregate production for accounting, including zero on failed steps; invalid survival state or overflow leaves world unchanged. Full climate, terrain suitability, ecology balance, long-distance search and founder recovery remain open. No imported upstream code; inspected ecosystem upstream's plant spawning and deliberately avoided population-targeted forced spawns.

## Increment 4 — bounded resource search
After urgent need and empty current stock, search Manhattan rings 1–8 for the nearest nonempty matching stock. Deterministic ties use ascending row then column; move one cardinal step, horizontal before vertical. At most 144 candidate positions, no extra RNG, no allocation; open terrain only. If none found remain idle. This improves local recovery but does not certify founder recovery from a fully depleted region, obstacle routing, or starvation balance. No new serialized fields. Tests exercise empty-tile traversal, consumption, radius, tie and invalid inputs.

## Increment 5 — common citizen identity, founder gestation, maturation
Partial G3. Shared Citizen record: stable uint64 ID, parent IDs (0 for founders), birth tick (0 for founders), existing position/traits/needs/action, primary purpose (none/gatherer/builder/inventor). Founders IDs 1 and 2 remain adults, immortal by identity, assigned a fixed purpose at initialization. Descendants occupy a bounded contiguous array of 254 slots, count 0–254, next ID=count+3 until death/archive is implemented. No slot reuse or deletion in this slice. Life stage derived from elapsed ticks (infant <2 years, child <12, adolescent <18, adult <55, elder thereafter); purpose chosen once at adulthood from strongest curiosity (inventor), diligence (builder), compassion (gatherer), in that tie order. All live agents use the same resource-consuming survival function, in ID order, including children (provisional independent self-care; parental care remains pending).
One founder-pair gestation record (due tick 0=none). At every 600th tick after survival, if both founders' hunger/thirst <=24 and Manhattan distance <=2, with free capacity and no pregnancy, use reproduction stream 1-in-4 draw to conceive; due in 16200 ticks (4.5 real hours). At due tick, birth occurs at founder 1's position; parent IDs 1,2; each trait is integer mean of parents plus uniform mutation -10..10 clamped 0..100. Birth occurs after survival, so newborn acts next tick. No other reproduction, pregnancy loss, health, mortality, archive or recovery certification yet. No conception when due tick would overflow. Gestation reserves one slot; invalid count/ID/parent/birth/purpose/position/needs/trait/gestation state rejected before mutation by step_world. Capacity is provisional pending board benchmarks. No new official saves; canonical serialization still pending. No forced population rescue or artificial divergence. Existing seasonal renewal occurs after lifecycle on its prior schedule.

## Increment 6 — mortality and lossless in-memory history
Provisional fixed limits: up to 254 live descendants and 512 lifetime descendant identities until durable archival storage is implemented. Each mortal has health 0–100 (live 1–100) and lifespan 60–80 simulated years (default fixture 70, seeded on birth by reproduction stream). Founders have health but cannot die; they remain at least 1 health and physically adult. After shared survival and clock advance, each citizen loses one health if either need is 100, recovers one if both needs <=24, otherwise unchanged. Mortals reaching zero die from dehydration if thirst is 100, else starvation; if still alive when age reaches lifespan, death cause is old age. Need-related death takes precedence. Before removal append full citizen snapshot, death tick and cause to fixed archive; stable compact live array maintains ascending ID order. Archive records ordered by death tick then ID within tick. Every issued ID 3..next_id-1 exists exactly once in live or archive, no ID recycling. Parent IDs still 1,2 in this slice. Capacity is reserved by lifetime admission: live+archive <=512; conception requires free active and lifetime capacity, so every admitted citizen can be archived. Full history defers reproduction explicitly (inspect history capacity); no history overwrites. This bounded RAM archive is not a durable save or five-year solution; disk archival is mandatory before release. Founders with health <50 cannot initiate conception; ongoing gestation unaffected until pregnancy loss is modeled. Tick order: validated survival, health/death, existing maturation/gestation, seasonal renewal. No illness, accident, parental care, descendant reproduction or full founder incapacitation yet. No third-party code copied.

## Increment 7 — multigeneration reproduction
Replaces founder-only due tick with one bounded world gestation slot: parent1 < parent2, due_tick, all zero when idle; cumulative lost_gestations (saturating uint64) until full event history. This single concurrent slot is provisional, not production population balance. Founder pair 1/2 or two distinct mortal adults (fictional inheritance, no human sex/genetic/inbreeding model). At each existing 600-tick opportunity, if active/lifetime capacity is available, count nearby eligible pairs in stable ID order and reservoir-select uniformly using reproduction stream; then one 1-in-4 conception draw. Both must be adult (not elder), health >=50, needs <=24, Manhattan distance <=2. Scan at most 32,640 pairs at current capacity, no heap. Ongoing pregnancy remains reserved; if either parent dies before birth, cancel and increment loss counter; no ID consumed. Otherwise at due tick create child at first parent's current position using actual parents' integer trait means, existing mutation and lifespan rules. No automatic rescue or pair selected by a global era. Parent IDs strictly lower than child, distinct, either 1/2 or both mortal, chronological parent age >=18 years and <55 at conception/birth eligibility is checked at conception; parent must have been born at least 18 years before child's birth and not died before birth. Archive references validated via bounded ID index. Live/archive records still exhaust lifetime admission ceiling. Provisional single gestation and orphan/self-care limitations must be addressed before G3 release certification. Existing survival, mortality, maturation and ecological renewal order retained.

## Increment 8 — dependent infants and parental care
At the beginning of a validated survival tick, infants (age <2 simulated years at pre-step clock) accrue needs once and do not independently forage or explore. Build a bounded parent-to-dependent request index from urgent infants in ascending ID order; an infant requests its living parents within one Manhattan tile. Each parent sees its lowest-ID eligible requesting infant, and may give care only when its own newly incremented needs are below 12, health >=50 and recipient has not already acted. Consume exactly one food/water unit from the parent's current tile, reduce the infant's greater need by up to 12 (ties water), mark infant eat/drink and parent care (action enum 4). If stock unavailable or already served, parent uses existing survival/exploration. No second consumption, no created stock. After adult/older-child actions, idle infants move at most one cardinal tile toward nearest living parent (tie lower ID); no independent wandering. This abstracts dependent transport, not physical infant locomotion. Orphan without living parents remains stationary and may die; non-parent care/adoption is pending. Stable order and bounded ID lookup; scratch index <=1030 bytes at provisional history ceiling. No new persistent fields beyond action enum. Existing mortality runs after care and may archive unserved infants. No full population viability claim; care thresholds and newborn biology provisional. All later event/knowledge systems must reuse the same resource and need transactions.

## Increment 9 — founder reunion and blocked-need recovery
No new persistent fields. During independent survival, prioritize the greater urgent need (ties water) using the existing local consumption and radius-8 search. If that resource is absent locally and the other need is urgent (>=12), attempt local consumption or radius-8 search for the other resource. For founders only, if neither urgent resource is locally reachable, use a bounded full-world nearest-stock scan, primary then urgent secondary, row-major ties. At most 6000 tiles per scan; no pathfinding obstacles yet. If no reachable stock exists, idle and wait for natural renewal. Consume exactly one unit via shared need transaction; movement at most one cardinal tile; no stock creation. After own needs and infant care are handled, when founders are farther than two Manhattan tiles apart, a nonurgent founder 1 stays in place while nonurgent founder 2 moves one cardinal tile toward founder 1 (horizontal first). Applies to all seeds, not a forced conception or guaranteed recovery; urgent needs and actual care take priority. At distance <=2 normal exploration remains. No reunion RNG draw. Rule order and thresholds provisional; same seed and state deterministic, no external clock. Regression tests isolate far resource access, secondary need, conservation and reunion. Full founder incapacitation, multi-pregnancy, long-run population balance and persistent archive still pending.

## Increment 10 — concurrent gestation
Replace single Pregnancy with bounded array of 128 records (at most half the 256 active citizens), active prefix pregnancy_count, unused records all zero. One person may participate in at most one pending pregnancy. Reserve one active descendant slot and one lifetime history identity per pregnancy; validate live count + pending <=254 and live + archived + pending <=512. Due ticks nondecreasing; same-tick records resolve in stable insertion order. Parents remain stable IDs, each pair ordered; all must be living adults or elders during gestation, adult only at conception. Validate before mutation. After mortality, cancel only records whose parent died, increment saturating loss counter, release reservation; deliver due births through shared inheritance and compact remaining records stably. Keep one global conception opportunity per 600 ticks, one eligible pair selected by existing reservoir rule excluding busy parents, one existing 1-in-4 roll; do not roll on a tick resolving birth/loss. No forced births or new RNG streams. No new imported code. Full population balance, parent care capacity, and removal of lifetime ceiling remain required; no production save format yet.

## Increment 11 — local orphan care
No new persistent fields. An infant with neither biological parent alive may request care from an eligible nearby adult or elder (including founders): health >=50, compassion trait >=50, hunger and thirst both <11 before the adult accrues its own needs. First reserve all ordinary parental requests exactly as before. In a second stable ascending infant-ID pass, an urgent orphan selects an unreserved eligible carer within Manhattan distance 1, prioritizing nearest distance, higher compassion, then lower ID. Each adult retains at most one request and uses the existing give_care and authoritative consume_need transactions; own survival still takes priority and a missing stock yields no care. In the dependent movement phase, an idle orphan without living parents may approach the nearest eligible adult within Manhattan radius 4 by one cardinal tile using existing dependent transport, with the same tie ordering; eligibility is reevaluated on current state. No remote rescue, guaranteed adoption, resources, RNG draws for care selection, changed biological identity, or persistent guardian assignment. If one parent survives, existing parental care applies. Selection scans at most 256 citizens per orphan per phase; benchmark worst-case before release. Thresholds provisional. Persistent adoptive households and long-run viability remain open.

## Increment 12 — persistent guardian identity
Citizen adds guardian_id and guardian_since_tick (uint64, zero pair when unassigned). An infant whose two biological parents are deceased records its first successful local carer as guardian at the current pre-step tick. Existing living guardian has first preference among eligible unreserved local carers, after biological requests; other adults may provide temporary assistance without replacing a living guardian. Dead guardian remains recorded until a new successful carer replaces it. Infant follows a living guardian only within existing four-tile awareness; otherwise existing local search. No changes to parent IDs, no extra consumption or RNG. Preserve latest relationship after maturity or death in the citizen snapshot. Earlier replaced relationships await durable journal. Validate both fields, adoption chronology during infancy, both biological parents dead by assignment, guardian exists and adult at assignment, not self/biological parent, and was alive then. Thresholds provisional; not a full household/adoption system.

## Increment 13 — newborn health and childbirth outcomes
Append health_events RNG stream after research (existing stream indices and initial values unchanged). BirthOutcome normal=0, complicated=1, fatal=2 stored on Citizen, founders normal. One draw in [0,9999] per delivered birth after existing inheritance. Provisional risk basis points = min(1500,100+10*(100-min parental health)+5*max(0,max parental hunger/thirst-24)), evaluated after survival and mortality at delivery. Roll below risk/5: immediate newborn death, health zero, archive at birth_tick with DeathCause childbirth=4; assign unique ID, release active slot, retain history. Otherwise roll below risk: newborn health 35, birth_outcome complicated, use ordinary care/recovery thereafter. Otherwise normal health 100. No parental injury/death in this slice; abstract two-parent model does not identify gestational parent. Existing loss before birth remains distinct, no ID issued. Reuse archive append primitive; stable death order (newborn IDs exceed all previously issued IDs). Capacity reservation unchanged. No draw for lost gestation. Validate enum and fatal/archived cause/tick consistency. Numerical rates are provisional simulation tuning, not human clinical estimates; no final balance claim. Disease-specific immunity and parental childbirth complications remain pending.

## Increment 14 — fictional disease and immunity
Two fictional disease catalog slots, each with resistance 0–100, remaining illness pulses and remaining immunity pulses (mutually exclusive). Separate seeded immunity_traits and disease_events streams appended after health_events. Founder resistance generated per slot, newborn resistance inherited mean plus bounded ±10 mutation, no inherited acquired immunity. Every 60 ticks after survival and before mortality, snapshot infectious status, apply one pulse of damage per active disease, founder floor 1, mortal floor 0. On final surviving pulse 75% chance of strain-specific temporary immunity. Suppress ordinary passive healing while infected; existing needs damage still applies. Mortality archives disease-caused zero health before needs update, no resurrection. Every pulse, susceptible citizens exposed to snapshot infectious neighbors within one Manhattan tile receive one bounded probability draw per strain, cap aggregate exposure and reduce by resistance. No newly infected transmission during same pulse. Every 3600 ticks, only if no active infection of strain, low-probability environmental introduction to one randomly selected live susceptible citizen, subject to resistance. No guarantee. Fixed bounded timers, no actual pathogen model, provisional simulation-only tuning. Preserve all existing streams and IDs. Newborns initially uninfected. Skip contact scans when no snapshot source; disease death requires retained illness provenance. No mutation, treatment, lifelong immunity or real epidemiological calibration in this slice.

## Increment 15 — disposable-world checkpoint and recovery
Explicit portable little-endian fields, no raw struct writes. PGCP format 1, rules revision 14, generation uint64 >0, bounded payload, CRC32 over header and payload. The same field visitor handles encode/decode. All current simulation fields and active record prefixes encoded. Reject invalid sizes/counts/checksum/magic/semantics before publishing decoded state; valid checksummed unsupported format or rules require migration, never silently overwritten. Two-slot recovery selects newest valid generation, reports degraded recovery on missing/corrupt peer; conflicting seeds, conflicting equal generations and decreasing tick order fail closed. No implicit new world. Host POSIX adapter writes a unique temporary file, fsyncs, reads back, renames into inactive slot, fsyncs directory. Requires isolated existing directory and serialized caller access; explicit creation only when both slots absent. Refuse backward tick and same-tick divergent state. This is a disposable-world checkpoint slice, not final UUID identity, event log, archive segmentation, JSON interchange, migration or ESP32 filesystem guarantee. A recovered older slot can lose progress since its checkpoint; report degraded recovery. Automatic cadence, storage admission and power-cut behavior pending. Existing 512 lifetime limit remains.

## Increment 17 — local density and resource stress
Every existing disease pulse snapshots alive/infectious state. For a susceptible nonimmune citizen with an infectious neighbor within Manhattan 1, count other people alive at pulse start in that neighborhood (not global population). Base existing contact/resistance risk p in basis points is adjusted by bounded odds multiplier m = 100 + 25*(clamp(neighbors,2,6)-2), expressed as percent. Integer adjusted probability = floor(10000*p*m/(100*(10000-p)+p*m)); 0 stays 0, 10000 stays 10000, no added RNG draw. Provisional local crowding proxy (not persons per room). Independent environmental introduction unchanged. No extra infection when no source outside environmental introduction; immunity and no same-pulse cascade unchanged. Existing disease damage d becomes d + floor(d*(clamp(max(hunger,thirst),60,100)-60)/40), a provisional acute stress proxy; never infer clinical malnutrition from need scores. Preserve founder floor, mortal death archive, no population quota. Worst-case contact scan remains quadratic, skipped without sources; snapshot costs one bounded bool array. Rules revision 15; no storage schema changes. Regression includes equal infectious contacts and equal RNG in sparse/crowded worlds, bounded monotonic odds, no-source case, immunity and health damage. Coefficients are tentative, evidence-informed not validated real-world rates; see POPULATION_EVIDENCE.md.
